候选 Deepening Opportunities

Strong

默认值与提示词的单一真实来源

Files: background.js · sidepanel.js · options.js · content.js

Problem：同一组默认常量在 4 个文件中复制粘贴（提示词、系统提示、默认设置）。这违反了 deletion test：删除副本后复杂度会“集中”，而非扩散。

Solution：抽取一个无 ES module 依赖的共享默认模块（如 extension/defaults.js），所有页面统一读取。

Benefits：改动只需触达一个 seam；后续 Candidates 2/3/4 的共享也会更自然。

Files: ai/providers.js · options.js · background.js (runtime handler)

SSE 解析逻辑共享

Files: background.js (parseOpenAISSE) · ai/client.js (drainSseStream + postSseMessage)

Problem：同一协议有两套解析实现；一套是 generator，一套是 callback，逻辑重复且维护负担翻倍。

Solution：把 chunk 解析提取为纯函数：输入原始文本流，输出结构化事件；再由不同调用方决定迭代方式。

Benefits：解析规则只在一处更新；双方都能受益于更完善的错误处理。

统一 streamChat

Files: background.js · ai/client.js

Problem：两处分别实现了请求、重试、流式消费与错误处理，但都不完整；想要 watchdog 又想要 retry 就必须合并。

Solution：以 ai/client.js 的版本为基础，加入 watchdog 与 abort meta；service worker 通过 offscreen document 复用同一实现。

Benefits：网络不稳定时两侧体验一致；测试只需覆盖一个函数。

content.js 深度拆分

Files: content.js

Problem：约 5700 行的单体脚本，混入状态管理、字幕抓取、Markdown/SRT/TXT 生成、阅读视图、播放器 AI 按钮与消息路由。

Solution：拆分为 state.js、subtitle.js、formatters.js、reader.js、player-ai.js、router.js。保持公开接口稳定，页面其余脚本按需引用。

Benefits：每个模块都可以单独阅读与测试；界面与数据之间有更清晰的 seam。

sidepanel.js 对话与上下文管理外置

Files: sidepanel.js

Problem：UI 绑定、provider 加载、上下文同步、会话持久化、消息渲染、流式 UI 全在同一作用域，导致理解任何一部分都需要先通读大量无关代码。

Solution：先把“会话生命周期 + 上下文 key 计算”抽出为独立模块，UI 只关心当前会话。

Benefits：UI 与状态分层；会话逻辑可被侧边栏与播放器 AI 按钮共享。

background.js 消息路由表驱化

Files: background.js (onMessage handler ~315 lines)

Problem：15+ message type 用 if-else 串接，新增 handler 需要翻找长链。

Solution：改为 Map<type, handler> 分发；保留参数校验与异步生命周期不变。

Benefits：新增能力变成局部改动；阅读器更容易知道“支持哪些消息”。
